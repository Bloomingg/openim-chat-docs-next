Synchronize a message event after OpenIM saves the message to the database. This callback is asynchronous and is intended for synchronization, auditing, or other background processing.

## HTTP request

```http
POST {WEBHOOK_ADDRESS}/callbackAfterMsgSaveDBCommand
```

## Request body

| Property | Type | Description |
| --- | --- | --- |
| sendID | string | User ID of the message sender. |
| recvID | string | Recipient user ID for a one-to-one or notification message. |
| groupID | string | Group ID for a group message. |
| callbackCommand | string | `callbackAfterMsgSaveDBCommand`. |
| serverMsgID | string | OpenIM server message ID. |
| clientMsgID | string | Client message ID. |
| operationID | string | OpenIM operation trace ID. |
| senderPlatformID | int | Platform ID used by the sender. |
| senderNickname | string | Sender nickname. |
| sessionType | int | Conversation type. |
| msgFrom | int | Message source. |
| contentType | int | Message content type. |
| status | int | Message status. |
| sendTime | int64 | Message send time as a Unix millisecond timestamp. |
| createTime | int64 | Message creation time as a Unix millisecond timestamp. |
| content | string | Message content, usually a JSON string for the message type. |
| seq | uint32 | Message sequence number. |
| atUserList | string[] | User IDs mentioned in the message. |
| faceURL | string | Sender avatar URL. |
| ex | string | Business extension data. |

For one-to-one or notification messages, `recvID` is populated and `groupID` is empty. For group messages, `groupID` is populated and `recvID` is empty.

## Response

Return HTTP success promptly with the common callback response. The message has already been saved to the database, so the response cannot change the write result.

```json
{"actionCode":0,"errCode":0,"errMsg":"","errDlt":"","nextCode":0}
```

## Processing rules

- Configuration key: `afterMsgSaveDB`.
- OpenIM sends this callback asynchronously after the message is saved.
- The message data and identifiers are sent in the JSON request body.
- Acknowledge quickly, then enqueue expensive work.
- Process idempotently using `serverMsgID`, `clientMsgID`, and the conversation identifier.
